---
title: Native linear DC
description: Explicitly compile and solve one native linear-DC request from project source or a verified bundle.
---

`volt simulate` is an explicit native linear-DC command. It binds an existing canonical
`DcRequest.to_json()` file to one exact logical Design, compiles through the native electrical
compiler, and solves only a complete model.

<Warning>
  This command does not infer a request from net names, ratings, or `volt.toml`. Regenerate the
  request after changing the logical design or its exact selected-Part closure.
</Warning>

## Run from project source

```sh
volt simulate --project samples/linear_dc --design divider \
  --request canonicalrequest.json --output source-dc --json
```

Omit `--project` to use normal project discovery. Source mode executes the configured project
entrypoint once in the isolated project worker and runs a returned `Project` only through its
design stage. It does not require a Schematic, Board, manufacturing output, or successful later
stage.

## Run from a source-free bundle

```sh
volt simulate --bundle divider.volt --design divider \
  --request canonicalrequest.json --output bundle-dc --json
```

`--bundle` and `--project` are mutually exclusive. Bundle mode verifies and opens the
ProjectBundle, selects the exact Design, and prepares its native input without project discovery,
source import, catalogue lookup, network access, or an external SPICE executable. Bundled
provenance source is never executed.

## Output contract

`--design`, `--request`, and `--output` are required. The output directory must not already exist.
Volt publishes the directory atomically and never modifies the request or input bundle.

| Native outcome | Status | Exit | Published sidecars |
| --- | --- | ---: | --- |
| Solve succeeds | `success` | 0 | `request.json`, `compile-report.json`, `solve-report.json`, `solution.json` |
| Compile is incomplete | `incomplete` | 1 | `request.json`, `compile-report.json` |
| Solve runs but fails | `failed` | 1 | `request.json`, `compile-report.json`, `solve-report.json` |
| Command, input, worker, I/O, or publication error | `error` | 2 | No success-looking partial output |

The canonical `request.json` and native `compile-report.json` are present whenever request binding
and compilation complete. `solve-report.json` exists only when the solver actually ran, and
`solution.json` exists only for a successful solve.

With `--json`, the versioned `volt.cli-result` envelope includes `status`, `design`, `source`,
`output`, `artifacts`, `compile_report`, and `solve_report`. The two report fields contain the
native report payloads; they are not Python reconstructions. `source` records either isolated
project provenance or the verified bundle digest and build identity.

## Scope and reproducibility

The first CLI slice uses the native default `DcSolveOptions`; it intentionally exposes no
numerical-setting flags. Supported behavior is independent DC over exact ideal linear resistor,
capacitor, and inductor models plus authored independent sources. Nonlinear, AC, transient,
sweeps, behavioural callbacks, and SPICE execution are outside this command.

Canonical request, compiled-model, report, and solution serialization is deterministic. Numerical
results are reproducible within the native solver's documented tolerances, not promised as
bit-for-bit identical across platforms. Ordinary check, build, export, and manufacturing commands
do not compile or solve automatically.

See the [runnable divider example](https://github.com/RyanWillie/Volt/tree/main/samples/linear_dc)
for request authoring and equivalent source/bundle invocations.
