01 / One owner for each fact

A model is not a new kind of Circuit component.

Component contractImmutable logical PinKeys, such as A and B.
Exact PartOne optional immutable R/C/L network, plus physical identity and existing V/I claims.
Circuit instanceOne exact selection. Existing pins and logical net membership.
Native analysisSeparate stimulus and reference. Read-only compilation, then later execution.

C++ owns all of this meaning, validation and persistence. Python supplies concise syntax. There is no ResistorComponent hierarchy, no new Circuit root methods, and no Python-only equation evaluator.

Existing Quantity, dimensions, tolerances and ranges already provide the foundation. Resistance, capacitance and inductance become proper model elements. Frequency and Time remain quantities and analysis coordinates.

02 / One small composition interface

A real capacitor can contain three ideal laws.

A ─ ESR ─ x ─ ESL ─ y ─ C ─ B

One physical Part. Three elements. Two private internal nodes. A second instance gets its own x and y.

component = library.component("C-ESR-ESL",
    pins=(volt.PinSpec("A", 1), volt.PinSpec("B", 2)),
    contract=volt.ComponentContract("example/capacitor@1", ("A", "B")))
cb = volt.PartElectricalModelBuilder(component)
p = cb.terminal("p", "A")
n = cb.terminal("n", "B")
x = cb.internal_node("after_esr")
y = cb.internal_node("after_esl")
cb.add(volt.ResistanceElement, "esr", p, x, volt.ModelParameter(volt.ohms(0.08)))
cb.add(volt.InductanceElement, "esl", x, y, volt.ModelParameter(volt.henries(1e-9)))
cb.add(volt.CapacitanceElement, "storage", y, n,
    volt.ModelParameter(volt.farads(10e-6), tolerance=volt.Tolerance.percent(0.20)))
capacitor = library.part("C-ESR-ESL", component=component,
    electrical_model=cb.build(), **physical_fields)

Component fields are authored once and reused by the native builder and exact Part. physical_fields supplies exact manufacturer identity, footprint and mappings; see the runnable authoring guide. One add operation accepts the closed native R/C/L types and owned handles.

Plain resistor

Bind A and B; add one resistance element with ohms(330) and Tolerance.percent(0.01). The nominal is 330 Ω; the bounds are 326.7–333.3 Ω. No special product class.

Three-terminal network

Two resistances connect A→COM and B→COM. Terminal currents are i₁, i₂ and −i₁−i₂. A terminal may have several incident branches; its current is their signed sum.

// Native C++ element insertion.
rb.add<ResistanceElement>(ModelElementKey{"body"}, a, b,
    ModelParameter{Quantity{UnitDimension::Resistance, 330.0},
                   Tolerance::percent(0.01), {}});
const PartElectricalModel model = rb.build();

The builder binds every contract pin exactly once, rejects foreign handles and dangling endpoints, then freezes an immutable model. The first vocabulary requires every declared terminal/node to participate in an element. Unused logical pins and partial IC behaviour remain unsupported; omission never means “open circuit.” Disconnected resistor-array subnetworks are valid.

# Select the exact Part and connect its logical pins.
c1 = design.instantiate(capacitor, ref="C1")
input_net.connect(c1["A"])
return_net.connect(c1["B"])
03 / Laws are not ratings

Nominal values have one authoritative home.

Each element stores one known nominal quantity, an optional tolerance and immutable evidence references. The nominal and whole tolerance interval must be finite and valid; tolerance deviations are finite and nonnegative, including explicit zero. No tolerance means uncertainty is unspecified; it does not mean perfect precision.

ElementOriented lawValue domain
Resistancev − R i = 0R ≥ 0. Zero means an exact voltage constraint, never division by zero.
Capacitancei − C dv/dt = 0C > 0. Zero is rejected.
Inductancev − L di/dt = 0L > 0. Zero is rejected.

For endpoints from→to, voltage is V(from)−V(to), and current is positive from→to. No epsilon clamp, invented leakage or automatic net merge makes a difficult circuit “work.” To omit a series parasitic, connect the remaining elements at the intended common endpoint.

Keep existing V/I claims

AcceptedRange, ProvidedRange, characteristics, limits and current requirements/capabilities retain their existing meaning. A capacitor voltage rating does not clamp its equation. A regulator guarantee is not an ideal source.

Do not duplicate Part truth

MPN, category, display values and old instance attributes never seed or override a model. Existing values retain their current owner; source migration must deliberately distinguish intrinsic model truth, independent intent and text.

No new canonical Power, Temperature, derating, internal-element rating or frequency-dependent law semantics are accepted here. Evidence may explain model fidelity without becoming executable applicability logic.

04 / Meaning survives without source

Save the exact model once, then resolve it.

  1. Part identity includes the model. Presence/absence, bindings, typed elements, ordered endpoints, local keys, normalized values, tolerances and evidence all participate.
  2. Canonical order is deterministic. Reordering declarations or using equivalent normalized units does not change identity. Reversing a branch changes its observation convention and identity. Absence is distinct from an empty/default model.
  3. Instances keep exact references. Multiple occurrences resolve one Part; each does not store a divergent model copy.
  4. Both bundles preserve closure. PartLibraryBundle and ProjectBundle carry the complete Part model plus referenced model and canonical V/I evidence. A logical-only project needs no Board.
  5. Native reopening uses vendored bytes only. No Python source, ambient library, network or cache supplies missing truth. Declared evidence with missing bytes is a structural closure failure.
Current-only persistence. E2 implements Part v6, ProjectBundle v3 and PartLibraryBundle v2. Readers reject malformed or incomplete closure; old artifacts are regenerated from source. The September amendment changes no formats.

The implemented selected-Part closure includes model and canonical V/I evidence, including logical-only projects.

05 / Equations first, execution later

A complete compilation is not a promised solution.

The compiler reads Circuit topology, the explicit exact-Part resolver and a separate native DC request. The planned output is a small typed resolved graph of nodes, oriented branches, R/C/L laws, source constraints, storage and stable origins. KCL derives from connectivity. It owns the result without modifying any input.

Testbench owns the question

Explicit DC voltage/current sources, reference net and probes. A source across an unmodeled supply does not clear missing coverage. Whole-occurrence exclusions or replacements must be explicit, reasoned and reported; completeness applies only to that stated analysis boundary.

Compiler owns the mapping

PinKey→instance pin→logical net, including hierarchical PortBindings. Internal nodes are private per instance. Unconnected pins get distinct derived nodes. No names, pads, ground labels or schematic wires create connectivity.

S1 owns request-local validation, exact binding and coverage. S2 owns expansion, hierarchical continuity and resolved-topology findings. S3 owns numerical lowering, rank/solvability, conditioning and residuals. Share native preparation rather than building competing resolution engines.

Canonical branches preserve observations, not a mandatory matrix unknown per element. Backends may eliminate coordinates only with deterministic reconstruction of requested currents/voltages, signs and origins. Nonunique currents remain nonunique; no arbitrary answer or hidden shunt repairs an ideal constraint.

KCL: +i leaves “from”; −i leaves “to”.

DC sets storage derivatives to zero: C imposes i=0; L imposes v=0. The compiled model still retains the original positive C/L values and storage laws. A capacitor across an ideal voltage source does not add an independent state merely because it is a capacitor.

CaseTruthful outcome
Absent Part modelValid authoring data; incomplete required analysis coverage.
Floating resistor islandUnfixed common-mode voltage; not automatically a contradiction.
Parallel unequal voltage sourcesInconsistent ideal constraints.
Parallel equal sources or ideal inductors in DCIndividual branch currents can be nonunique.
Wrong units, foreign identities or corrupt closureReject at the owning native boundary, not a harmless warning.

Ordinary check/build/manufacturing never launches a solver. Numerical algorithms, SPICE lowering and results come later, consuming this same meaning and reporting limitations without changing Part or Circuit truth.
