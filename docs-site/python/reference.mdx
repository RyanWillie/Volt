## Native Part electrical models

Declare component fields once with `Library.component(...)`, pass the returned
`PartComponentDefinition` to `PartElectricalModelBuilder(component)`, then attach its finalized
model with `Library.part(..., component=component, electrical_model=model)`.
The single `add(element_type, key, from_, to, parameter)` operation accepts exactly the
native R/C/L or Shockley diode element classes and builder-owned handles. Python does not own model
validation, unit conversion, identity or serialization.

| Export | Purpose |
| --- | --- |
| `volt.PartComponentDefinition` | Reusable owning native component definition for model authoring and exact Parts. |
| `volt.PartElectricalModelBuilder` | Native append-only builder with `terminal`, `internal_node`, generic typed `add` and immutable `build`. |
| `volt.PartElectricalModel` | Complete immutable model for one exact component identity, with terminal, internal-node and element inspection. |
| `volt.ModelParameter` | Native nominal Quantity, optional normalized tolerance and immutable evidence hashes. |
| `volt.DiodeParameters` | Native positive Is/n parameters, fixed per-element temperature, bounded mild-reverse voltage domain, and immutable condition evidence. |
| `volt.ShockleyDiodeElement` | Explicitly oriented idealized anode-to-cathode Shockley law, added through the existing generic builder with DiodeParameters. |
| `volt.ResistanceElement` | Oriented ideal resistance with finite nonnegative value and bounds, including zero ohms. |
| `volt.CapacitanceElement` | Oriented ideal capacitance with finite positive value and bounds. |
| `volt.InductanceElement` | Oriented ideal inductance with finite positive value and bounds. |
| `volt.ModelTerminal` | Immutable binding of a model terminal key to a contract PinKey. |
| `volt.ModelInternalNode` | Immutable private node inaccessible to Circuit connectivity. |
| `volt.ModelTerminalKey` | Stable model-local terminal identity. |

Bare numbers do not supply model parameters. Omitted models stay absent; instance values or
display strings never infer or override intrinsic Part parameters. Models are ideal laws,
separate from canonical Voltage/Current ratings and physical guarantees. An unmodeled LED or
IC remains unsupported, and defining a passive model does not certify full-design simulation.
The [runnable examples](https://github.com/RyanWillie/Volt/tree/main/samples/electrical_part_models)
demonstrate a resistor, ideal C/L, a composite C+ESR+ESL Part, and source-free bundle reopening.

## Explicit DC solving

`volt.solve_dc` evaluates an explicitly compiled `volt.CompiledElectricalModel` in process.
`volt.prepare_ngspice_dc` deterministically projects the same complete model to the bounded
ngspice 46 DC contract; callers may execute its generated `deck` and pass the exact output bytes
to `volt.solve_ngspice_dc`. Neither route implicitly compiles a request or runs during ordinary
project builds, checks, or manufacturing.

The default native method and ngspice route support the bounded linear R/C/L and
independent DC-source vocabulary. A linear solve
publishes a solution only when native uniqueness, conditioning, finiteness, and residual gates
pass; rank-deficient, inconsistent, ill-conditioned, nonfinite, and residual failures remain
typed reports with diagnostics and available metrics. The low-level Python API never starts an
external process; use the explicit CLI backend for bounded ngspice execution.

| Export | Purpose |
| --- | --- |
| `volt.NonlinearDcSolveOptions` | Explicit native diode Newton method with physical acceptance gates and bounded iteration, backtracking, residual and Jacobian work. |
| `volt.DcSolveOptions` | Validated typed numerical thresholds with deterministic defaults and scaling policy. |
| `volt.DcSolveOutcome` | Closed success and numerical-refusal outcome enum. |
| `volt.DcSolveMetrics` | Available coordinate-count, rank, conditioning, and residual evidence. |
| `volt.DcSolveReport` | Immutable attempt retaining model, options, identities, outcome, metrics, and diagnostics. |
| `volt.DcSolveProvenance` | Backend, adapter, settings, validation, and optional deck/mapping attribution retained by reports and solutions. |
| `volt.DcSolution` | Success-only immutable model-order node, branch, and request-probe observations. |
| `volt.DcNodeResult` | One model-local node index and finite potential. |
| `volt.DcBranchResult` | One model-local branch index with oriented voltage, current, and signed absorbed power. |
| `volt.DcProbeResult` | One request-local probe key and native-dimension value. |
| `volt.solve_dc` | Evaluate one complete compiled model with validated options. |
| `volt.NgspiceDcAnalysis` | Immutable generated deck, exact model, completeness, diagnostics, and deck/mapping identities. |
| `volt.prepare_ngspice_dc` | Project one complete compiled model into the closed ngspice 46 DC adapter contract. |
| `volt.solve_ngspice_dc` | Parse adapter-owned machine output bytes and apply native result acceptance. |

For an idealized diode operating point, explicitly call
`volt.solve_dc(model, volt.NonlinearDcSolveOptions())`; the default linear method refuses
diode laws. In source or source-free bundle CLI mode use `--method diode-newton` with
DC and the native backend. Python binds native values and orchestrates execution.
The native model keeps each prescribed fixed temperature without rescaling Is; its
inclusive voltage domain must contain zero and satisfy the mild-reverse bound
`vmin >= -3*n*k*T0/q`. It excludes ordinary rectifier reverse operation and breakdown.
Evidence absence means uncalibrated, and illustrative evidence does not establish
manufacturer accuracy. Native acceptance requires original laws, all-node KCL, an
undamped correction, and final Jacobian rank/condition. Convergence is a locally regular
accepted point, with no global convergence or uniqueness guarantee. Failure retains
available metrics and exact identities without a solution. AC, transient and public
ngspice capability checks refuse diode execution; sweeps remain deferred.
See the [executable diode example](https://github.com/RyanWillie/Volt/tree/main/samples/nonlinear_dc)
and [bounded contract](https://github.com/RyanWillie/Volt/blob/main/docs/nonlinear-dc.md).

The coordinate indices are scoped to the retained compiled model; they are not generic mutation
handles. `NgspiceDcAnalysis.to_json()` exposes the deterministic mapping needed to audit generated
device/vector names when lowering is available. Diode lowering returns an incomplete report
with branch provenance, an unavailable mapping and no executable deck. It does not accept
arbitrary SPICE text. Eigen and ngspice remain private
implementation/execution choices, and no backend matrix or vector type crosses the native or
Python API.
