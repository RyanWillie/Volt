Volt · Linear DC · S5

ngspice is an execution target, not a second source of truth.

Volt first binds a canonical request and compiles its exact selected-Part closure into one immutable native electrical model. Only then can prepare_ngspice_dc(model) generate a closed ngspice 46 deck and mapping. External numbers become a Volt solution only after solve_ngspice_dc(analysis, output) reconstructs them and applies native acceptance.

One model, two explicit executions

request → native compile → complete model
                           ├─ solve_dc(model)
                           └─ prepare_ngspice_dc(model)
                                → generated deck → ngspice 46
                                → solve_ngspice_dc(analysis, output bytes)

No operation is implicit in project import, check, build, export, or manufacturing. The Python preparation/ingestion API does not start processes. The CLI starts one only when the user selects --backend ngspice and supplies --ngspice /exact/executable.

The projection is deliberately smaller than SPICE

Native lawExact DC projection
Positive resistanceOne resistor with the native orientation and nominal value
Zero-ohm resistanceIdeal 0 V source, never backend-specific zero-resistor behavior
CapacitanceDC-open; exact zero current is reconstructed by native policy
InductanceDC-short with an externally observed identifiable branch current
Independent sourceAuthored value and ordered endpoints

There are no convergence shunts, epsilon resistors, hidden parasitics, includes, model cards, vendor libraries, arbitrary control scripts, nonlinear devices, AC, transient, or sweeps. An unsupported or incomplete model stays incomplete; it is not silently approximated.

The executable is untrusted

The CLI accepts exactly ngspice 46. It invokes the resolved path directly without a shell, uses -n to disable user startup files, provides a private working/configuration directory and controlled locale, closes stdin, and enforces fixed time and byte ceilings. Version mismatch, startup failure, timeout, oversized logs/data, nonzero exit, missing output, malformed headers, nonfinite numbers, and extra operating points fail without retry or native fallback.

The generated deck owns a single op and machine-readable wrdata command. The native parser requires the exact ordered header contract and one finite row; console text is evidence, never the numerical API.

Identity follows the numbers

NgspiceDcAnalysis retains the compiled model plus deterministic deck and mapping identities. The published analysis records model/request identity, generated device and vector names, reconstruction policy, output filename and byte limit. The solve report and success-only solution repeat backend/adapter versions, effective settings, native acceptance policy, validation backend, deck identity, and mapping identity.

Serialization is deterministic. Floating-point agreement is tolerance-based: cross-platform or cross-backend results are not promised bit-for-bit. Volt rechecks the reconstructed solution against the original laws, including reference potential and all-node KCL; convergence alone cannot certify success.
