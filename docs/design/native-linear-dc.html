Volt · Native linear DC · S3

A DC answer must earn its success.

volt.solve_dc(model) evaluates one complete, immutable compiled electrical model. It returns every node potential, every oriented branch voltage/current and signed absorbed power, and all requested probes—but only after uniqueness, conditioning, finite arithmetic and residual checks pass. A small residual alone is not enough.

The whole public workflow

compiled = volt.compile_electrical(request)
if compiled.complete:
    report = volt.solve_dc(compiled.model)
    if report.success:
        solution = report.solution
        for probe in solution.probes:
            print(probe.key.value, probe.value.value)
    else:
        print(report.outcome, report.diagnostics)
        print(report.metrics.rank, report.metrics.reciprocal_condition)

The C++ entry point is solve_dc(const CompiledElectricalModel&, const DcSolveOptions&). The compiled model already owns the exact request, input and selected Parts. No independent Circuit, resolver, new readiness engine or graph authoring interface enters the numerical service.

Equations without hidden substitutions

The small dense backend uses one voltage for every non-reference node and one current for every branch. Rows are non-reference KCL followed by the original DC branch laws. This branch-tableau formulation avoids dividing by resistance and leaves ideal-branch currents visible to the rank test.

BranchDC equationWhat remains observable
Resistance, including R = 0v − Ri = 0Stored orientation, voltage, current and power
Capacitancei = 0Voltage and zero steady current; original positive C stays in the model
Inductancev = 0Identifiable current; original positive L stays in the model
Voltage sourcev = authored voltageSource current; delivering power normally has negative current
Current sourcei = authored currentSource voltage and signed absorbed power

Here v = V(from) − V(to), and positive current leaves from. Power is p = vi. Coincident endpoints cancel KCL incidence, not the law or its current: an ideal zero-voltage self-loop still has an undetermined current and must not become a successful zero.

The acceptance policy is explicit

DcSolveOptions validates finite, strictly positive settings. Relative settings must also be below one; absolute quantities must have the correct voltage/current dimensions. These are numerical policies, not parasitic components or physical uncertainty. No library-default threshold silently replaces them.

Eigen 5.0.0 FullPivLU supplies the established rank-revealing factorization and reciprocal-condition estimate. It is a private header-only implementation dependency pinned by archive SHA-256; public headers and the installed SDK expose no Eigen types or package dependency.

Two residual checks, different meanings

The dimensionless algebraic check is ‖Aₛy − bₛ‖∞ / (‖Aₛ‖∞ ‖y‖∞ + ‖bₛ‖∞), with zero residual for the all-zero case. After reconstruction, every original electrical equation is checked in its own SI units:

  • KCL at all nodes, including the omitted reference row: absolute current tolerance plus relative tolerance times the sum of absolute incident currents.
  • Resistance and voltage-source laws: absolute voltage tolerance plus relative tolerance times the sum of absolute terms being compared.
  • Inductor voltage, capacitor current, current-source law and explicit reference potential use the same absolute-plus-relative rule in their respective dimensions.

Nonfinite assembly, factorization, reconstruction, power, probe values or residual arithmetic fails the attempt. No shunt, epsilon resistance, regularization, least-squares answer or minimum-norm current is substituted. Rank and conditioning are numerical assessments under the effective policy, not exact symbolic proofs.

Failure is a useful result—not a fake operating point

The typed outcomes distinguish success, rank deficiency, inconsistency, unacceptable conditioning, numerical failure and residual failure. Rank-deficient cases may use the normalized augmented matrix rank to identify inconsistency; uncertain physical causes remain a conservative numerical classification. Available metrics are retained, and uncomputed metrics are absent. Failed reports have no solution.

Floating resistor islands, capacitor-only unfixed potentials and nonunique parallel ideal currents are explicit failures. Globally inconsistent source loops are checked here, after S2 has already handled its simpler local topology contradictions.

Traceable results and independent proof

Solutions retain their model, effective options and analysis identity. That identity includes the compiled input, numerical contract, backend and every setting—not machine paths or floating-point outputs. Node/branch IDs resolve directly to the original compiled origins; probe keys retain the request's orientation. Native/Python snapshots match within one build; cross-platform numbers are compared with explicit tolerances, not promised bitwise equality.

The versioned test corpus includes hand-authored ngspice-46 decks and independent analytical expectations for dividers, loads, source polarity, zero-ohm constraints, ideal C/L and composite storage. The zero-ohm oracle is an explicit 0 V constraint, not ngspice's backend-specific zero resistor behavior. Degenerate oracle behavior cannot certify native success.

Inspection JSON is owner-local output, with no result reader or new ProjectBundle schema. Source-free operation reopens existing verified inputs, then compiles and solves them. Ordinary builds and manufacturing remain solver-free; canonical Circuit, Part, Board and Schematic truth is unchanged.
